## ⚠️ Proposed by M7's milestone review, and NOT yet decided

**An assembly milestone before M8.** It is not in the table above, because a
milestone that changes the execution order is a decision and belongs in an ADR
rather than in a row marked "proposed" — review of M7.15 made that point and it
is right.

⚠️ **THERE IS STILL NO PRODUCTION `main()` IN THE TREE**, and M7 added six unwired mechanisms to the four M5.91 already records and M6.19's routed path. A chaos matrix demonstrated against a system no code assembles is MODELLED, not measured — which is the argument the M9 row already makes in writing about the backend, and it applies to assembly identically. Concretely: `SIGSTOP` on a pod that runs no retention loop cannot show GC stopping, and an AZ partition cannot show that a fenced GC deletes nothing, because nothing composes `LeasedGc` with `RetentionPass` — and the minor at `058b0bb` records that composing them the obvious way "compiles, passes, and deletes unfenced", which is a silent data-loss path M8 would be the natural place to catch and cannot. It is not new design: every piece is built and tested, and what is missing is the composition, which is where three recorded defects live (the unfenced GC, the chain's cost, the batch size). Would carry M5.91, M6.15, M6.19, M7.17, M7.18, M7.19, M7.25 and M7.26

⚠️ **It is recorded here rather than acted on**, and the next session either
writes the ADR or says why M8 can start where it stands.
