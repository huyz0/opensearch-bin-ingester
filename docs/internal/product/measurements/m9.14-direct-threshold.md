# M9.14 direct-threshold measurement

Status: measured on the local RustFS rig on 2026-09-23. Request counts and byte
counts are observed. CPU times are local process observations, not production
capacity claims. S3 TTFB is NOT-RUN.

## Method

`DirectThresholdMeasurementIT` ran the production `SubscriptionHub` serving
path against a 64 KiB RustFS object for each fan-out from 1 through 16. It used
one cold publish to measure the proxy GET (through `CountingBinStore`) and
warm the node cache, then a 1,000-delivery batch to measure steady-state serving
CPU. Direct-mode request counts are independent HTTP GETs made with the issued
presigned URLs; every returned status and complete body was checked. Each
point was repeated three times; CPU is the median per-delivery process CPU
delta, with min/max across repetitions. Segment bytes are counted at the
ingester sinks; signed-URL segment bytes do not pass through those sinks.

The process CPU counter includes JVM work outside the serving code and its
15.625 μs sampling granularity is visible in many proxy readings. The printed
values are nanoseconds per delivery: that batch-level clock step normalizes to
15.625 ns per delivery over 1,000 calls. Treat CPU as a coarse local comparison
only. It does not isolate a production pod, and it is not used to price the
threshold. No S3 TTFB or latency comparison is claimed.

The direct request counts above are actual successful HTTP reads, not presign
calls. Presigning itself is local and is not a store request. The test also ran
the configured default at each fan-out: it selected direct at 1, then proxy at
2–16. Proxy's cold miss cost was exactly one GET at every fan-out; direct cost
was exactly N GETs. The default's 64 KiB cold segment therefore costs one GET
in either mode at fan-out 1 and keeps the lower one-GET proxy path above 1.

## Cost-only conclusion

At the AWS S3 Standard GET price in the research cost table ($0.0004 per 1,000
GETs), fan-out 1 is the only point where direct does not increase request
cost: both paths cost one GET ($0.0000004 per segment). At fan-out N > 1,
direct costs N GETs versus proxy's one; at N=16 that is 16× the requests
($0.0000064 versus $0.0000004 per segment). Same-region S3-to-EC2 transfer is
priced at zero in that table, so there is no byte-transfer dollar credit to
offset those extra GETs. Keep the default direct threshold at **1**. This is a
cost-parity boundary, not a measured latency crossover, and the coarse CPU
readings do not establish a CPU-cost saving.

The result artifact and the cost-only decision are carried into the M9.15
generated curve. M9.15 must preserve the distinction between observed request
counts, local CPU observations, modelled dollars, and unmeasured cloud latency.
