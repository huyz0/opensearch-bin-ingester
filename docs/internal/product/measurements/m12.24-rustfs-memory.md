# M12.24 RustFS fixture memory, on M9's rig

Status: measured on 2026-09-29, on M9's rig. `docker-compose.test.yml`'s RustFS
`mem_limit` is raised from 256m to **1g**. `PartitionVisibilityIT`'s 2,500 ms
bound is unchanged.

## Rig

As `m11.23-partition-visibility.md` records: Intel Core i5-13600KF (14 physical /
20 logical cores), Windows 11 Pro build 26200, Temurin 25.0.4.1, Docker Desktop
29.8.0 with 20 CPUs and 31.3 GiB (re-read on this run with `docker info`).

⚠️ **Not an idle rig.** Other projects' containers ran throughout: two
`oqueue-test` containers and three `pstore-dev` ones (RustFS, Azurite, a fake
GCS). Nothing else from this repository ran.

## Runs

Each run is `./gradlew :server:integrationTest --rerun --tests
'*PartitionVisibilityIT'`, one after another on the SAME RustFS container (the
fixture starts it once and leaves it running; `docker compose up` recreated it
when the limit changed). Memory is `docker stats` of the container after the run.

| 1 | 512m | 160 ms | 1,596 ms | green | 428 MiB (84%) |
| 2 | 512m | 362 ms | 1,890 ms | green | 462 MiB (90%) |

| 4 | 512m | 156 ms | 1,618 ms | green | 477 MiB (93%) |

No run was OOM-killed (`docker inspect ... State.OOMKilled` false after runs 6 and
9).

## What it shows, and what it does not

- **At 512m three consecutive green runs were not observed.** Of five runs that
  reached M=1,000, one drained over the bound (run 6, 4,074 ms, its trigger
  write answered in 92 ms). RustFS ended every run at 84-93% of its limit.
- **At 1g, 3 of 3 consecutive runs were green**, the criterion M12.24 names.
- ⚠️ **RustFS's usage grew across consecutive runs on one container** (462, then
  685, then 709 MiB at 1g). 1g is what was measured to be enough for three runs;
  it is NOT shown to be a plateau. A longer sequence on one container may reach
  the limit again. That RustFS is the cause of run 6's slow drain is the
  fixture-level reading M11.23 established at 256m; at 512m it is a correlation
  with the memory near the limit, not a measured cause.
- **Run 3 is not a memory failure.** `NodeProcess` picks a pod's port by opening
  and closing a probe socket and passing the number to the child, which can lose
  the port to another process in between (port 50174 is outside Windows'
  excluded ranges). That race is its own backlog row, M12.28.

## Budget

The configured limits `scripts/test_budget.py` sums: Gradle daemon 1,024 MiB, two
compile daemons 1,024, two test JVMs 1,024, RustFS 1,024 -- **4,096 MiB**, inside
build.md's 6,144 MiB ceiling. build.md's allocation table now reads 6,656 MiB of
the 8 GiB per-session budget.
